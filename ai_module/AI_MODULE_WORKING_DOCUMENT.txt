A. MODULE OVERVIEW
================================================================================
1. What the AI Module Is:
The AI Module (`ai_module/`) is the central content generation and adaptive
pedagogical engine for the "AI-Based Personalized Learning Content Generator"
system. It is a standalone, self-contained Python package that bridges the
application with Google's Gemini Large Language Model (LLM) while maintaining
strict structural and deterministic control over all outputs.

2. Problem It Solves:
Standard online learning platforms deliver identical, static content to all
students regardless of their background knowledge, comprehension speed, or
test performance. Beginners are frequently overwhelmed by dense technical
jargon, while advanced students waste time reading introductory summaries.
Furthermore, raw generative AI models are unpredictable: they often produce
inconsistent formats, varying question counts, and unstructured text that
crashes downstream web applications.

The AI Module solves this dual problem by:
a) Programmatically tailoring technical explanations, summary notes, and quizzes
   to three distinct competency levels: Beginner, Intermediate, and Advanced.
b) Guaranteeing 100% parseable, strictly typed JSON data structures matching
   an explicit schema (including exactly 12 multiple-choice questions per module).
c) Deterministically calculating progression and regression across difficulty
   tiers based on student quiz scores.

3. Purpose Within the Overall Project:
In the four-member team architecture:
- User (AI Lead): Built `ai_module/` (this module).
- Rounak (Backend Lead): Builds `backend/` (FastAPI REST APIs, SQLite/PostgreSQL
  database, session storage, quiz scoring).
- Junaid (Frontend Lead): Builds `frontend/` (React/Next.js interactive UI).
- Varun (Docs/Presentation Lead): Writes project reports and defends the system.

The AI Module serves as the backend's internal library. When a student requests
a lesson on any topic (e.g., "Python Memory Management" or "Binary Search"),
the backend invokes this module to receive a complete, verified pedagogical
unit.

4. Responsibilities and Strict Boundaries:
WHAT THE AI MODULE DOES:
- Validates user input (topic and difficulty level) before making network calls.
- Constructs deterministic, pedagogically sound prompts.
- Interacts with Google Gemini using the official `google-genai` SDK.
- Enforces strict JSON Schema validation via Pydantic v2.
- Protects API credentials by sanitizing errors and masking secrets.
- Implements rule-based adaptive difficulty transitions (promotions/demotions).

WHAT THE AI MODULE DOES NOT DO (STRICT SYSTEM BOUNDARIES):
- Does NOT start a web server or handle HTTP request/response lifecycles.
- Does NOT store data in databases or manage user sessions.
- Does NOT grade student quiz submissions (the backend compares student answers
  to the correct answer key).
- Does NOT calculate the student's score percentage (the backend evaluates
  answers and passes the numeric percentage to the AI module).
- Does NOT render frontend UI components.

B. TECHNOLOGY STACK & ROLE ANALYSIS
================================================================================
The AI Module deliberately uses a lightweight, modern, and production-grade
technology stack. All dependencies are recorded in `ai_module/requirements.txt`.

1. Python 3.12 (Core Language):
- Role: Provides the runtime environment, strong typing capabilities via the
  `typing` module (`Literal`, `Optional`, `Union`, `Any`), and native unittest
  framework.
- Rationale: High developer velocity, seamless integration with AI libraries,
  and clean structural syntax.

2. Google Gen AI SDK (`google-genai>=1.0.0`):
- Role: The official, next-generation Google Gemini Python client.
- Imported as: `from google import genai` and `from google.genai import types, errors`.
- Rationale: Replaces the legacy `google-generativeai` package. Supports modern
  Gemini 2.5/3.5/3.8 endpoints, direct OpenAPI 3.0 schema injection via
  `types.GenerateContentConfig`, and fine-grained error types (`errors.APIError`).

3. Pydantic v2 (`pydantic>=2.0.0`):
- Role: Data validation, contract enforcement, and JSON serialization.
- Used components: `BaseModel`, `Field`, `ConfigDict`, `field_validator`,
  `model_validator`, `ValidationError`.
- Rationale: Guarantees that raw LLM text is mathematically checked against
  business constraints (e.g., exactly 12 questions, exactly 4 distinct options,
  correct answer matching an option) before reaching the backend. Pydantic's
  `model_dump()` provides a clean dictionary ready for FastAPI serialization.

4. Python Standard Library:
- `os` and `sys`: Environment variable inspection (`GEMINI_API_KEY`, `GEMINI_MODEL`)
  and runtime path resolution.
- `math`: Finite number and NaN/Infinity validation in difficulty calculations.
- `unittest` and `unittest.mock`: Hermetic test execution with zero external test
  runner dependencies.
- `json`: Parsing and mock serialization for offline integration tests.

C. ARCHITECTURE & FILE RESPONSIBILITIES
================================================================================
The `ai_module/` directory consists of 6 primary source code files, 5 dedicated
unit test suites, 2 operational demo/test scripts, and 2 documentation files:

1. `ai_module/__init__.py` (Package Root):
- Defines the public API exposed to Python callers.
- Exports: `generate_adaptive_content`, `calculate_next_level`, `LearningModule`,
  `QuizQuestion`, `build_prompt`, `VALID_DIFFICULTIES`, and `GeminiService`.

2. `ai_module/schemas.py` (Data Models & Validation):
- Contains Pydantic schemas:
  * `QuizQuestion`: Represents one multiple-choice question.
  * `LearningModule`: Represents the complete educational payload.
  * `_strip_additional_properties`: Custom schema cleaner that removes
    `"additionalProperties": false` from the exported JSON schema to prevent
    Google Gen AI's OpenAPI 3.0 parser from throwing a 400 Bad Request error.

3. `ai_module/prompts.py` (Prompt Construction Engine):
- `VALID_DIFFICULTIES`: Dynamically extracted from `LearningModule` type hints
  (`("Beginner", "Intermediate", "Advanced")`) ensuring a single source of truth.
- `LEVEL_GUIDELINES`: Dictionary mapping difficulty tiers to specific pedagogical
  instructions.
- `build_prompt(topic: str, difficulty_level: str) -> str`: Constructs a clean,
  deterministic prompt text instructed to generate exactly 12 MCQs.

4. `ai_module/gemini_service.py` (Gemini API Bridge):
- `DEFAULT_GEMINI_MODEL`: Constant set to `"gemini-3.5-flash-lite"`, verified
  for high reliability and structured output support.
- `GeminiService`: Class handling client instantiation, reading API keys from
  `os.environ["GEMINI_API_KEY"]`, configuring `response_schema=LearningModule`,
  executing API requests, redacting credentials upon error, and validating outputs.
- `generate_learning_content(...)`: Convenience helper function for one-off calls.

5. `ai_module/difficulty.py` (Rule-Based Adaptation Engine):
- Pure algorithmic progression logic (zero network/LLM dependencies).
- `calculate_next_level(current_level: str, score_percentage: Union[int, float]) -> str`:
  Evaluates student quiz performance and computes the next difficulty level.
- Validates scores in range [0.0, 100.0], checks for non-numeric/NaN inputs,
  and enforces boundary clamping (`Beginner` floor, `Advanced` ceiling).

6. `ai_module/adaptive_tutor.py` (Primary Public Facade):
- Exposes `generate_adaptive_content(topic, difficulty, api_key=None, model_name=None)`:
  The single function Rounak imports in FastAPI.
- Validates parameters, initializes `GeminiService`, generates the validated
  `LearningModule`, and exports it as a Python dictionary (`model_dump()`).
- Re-exports `calculate_next_level` for clean import paths.

7. Operational Scripts:
- `demo_end_to_end.py`: End-to-end demonstration running offline or live.
  Simulates Beginner module creation, 100% quiz score promotion, Intermediate
  follow-up creation, 40% score demotion, and 50% score maintenance.
- `example_usage.py`: Minimal caller reference script showing basic usage.
- `integration_test_live.py`: Real-network integration test verifying real

8. Integration Contract:
- `INTEGRATION_CONTRACT.md`: Complete technical specification for backend lead
  Rounak, including schemas, error handling tables, and a full FastAPI reference

D. COMPLETE EXECUTION FLOW & MERMAID FLOWCHART
================================================================================
The execution flow separates input validation, prompt synthesis, network
transport, and schema enforcement into distinct, verifiable stages.

Step-by-Step Flow:
1. Public Entry: The caller (e.g., FastAPI backend) calls:
   `generate_adaptive_content(topic="Python Memory Management", difficulty="Beginner")`
2. Input Validation:
   - `adaptive_tutor.py` checks that `topic` is a non-empty string.
   - Verifies `difficulty` belongs to `("Beginner", "Intermediate", "Advanced")`.
   - If invalid, immediately raises `ValueError`. No API call or client init occurs.
3. Service Initialization:
   - `GeminiService` reads `GEMINI_API_KEY` from the environment or parameter.
   - If missing, immediately raises `ValueError`.
   - Configures the target model (`gemini-3.5-flash-lite` or `GEMINI_MODEL` override).
   - Instantiates `genai.Client(api_key=...)`.
4. Prompt Construction:
   - `prompts.build_prompt(topic, difficulty)` selects guidelines for the level.
   - Assembles an instruction template requiring an explanation, 3-5 notes,
     and exactly 12 four-option MCQs.
5. Structured Request Configuration:
   - Creates `types.GenerateContentConfig`.
   - Sets `response_mime_type="application/json"`.
   - Sets `response_schema=LearningModule` (with stripped additional properties).
   - Sets `temperature=0.3` for consistent, deterministic generation.
6. Gemini Network Request:
   - `client.models.generate_content(...)` transmits the prompt and schema to Google.
   - If the network fails, or credentials fail, or Gemini returns 503:
     Exception text is sanitized (API keys replaced with `[REDACTED]`) and
     re-raised as a clean `RuntimeError`.
7. Pydantic Runtime Validation:
   - Gemini returns a JSON string in `response.text`.
   - `LearningModule.model_validate_json(response.text)` parses the JSON.
   - Checks:
     * Are there exactly 12 questions in the quiz list?
     * Are there between 3 and 5 revision notes?
     * Does each question have exactly 4 choices?
     * Are all 4 choices distinct?
     * Does `correct_answer` match one of the 4 choices?
     * Are there forbidden extra fields?
   - If any rule is violated, raises `ValueError`.
8. Final Dict Serialization:
   - `learning_module.model_dump()` converts the verified Pydantic model into a
     standard Python dictionary.
   - Returned to backend for immediate JSON transmission to the frontend.

Mermaid Architecture & Flow Diagram:
```mermaid
flowchart TD
    A[Backend Caller / FastAPI] -->|topic, difficulty| B[generate_adaptive_content]
    
    subgraph Validation Phase
        B --> C{Validate Topic & Difficulty}
        C -->|Invalid| D[Raise ValueError 422]
        C -->|Valid| E[Initialize GeminiService]
        E --> F{Check GEMINI_API_KEY}
        F -->|Missing| G[Raise ValueError 500]
    end

    subgraph Generation Phase
        F -->|Present| H[build_prompt: Level Guidelines]
        H --> I[Configure GenerateContentConfig: schema=LearningModule, temp=0.3]
        I --> J[genai.Client: models.generate_content]
    end

    subgraph Transport & Security
        J --> K{API Call Success?}
        K -->|Network / Auth Error| L[Sanitize Secret -> Redact -> Raise RuntimeError]
        K -->|Success| M[Raw JSON Text Response]
    end

    subgraph Schema Enforcement
        M --> N[LearningModule.model_validate_json]
        N --> O{Pydantic Validation Check}
        O -->|11 or 13 MCQs / Bad Schema| P[Raise ValueError]
        O -->|Valid 12 MCQs, 3-5 Notes| Q[learning_module.model_dump]
    end

    Q --> R[Return Python Dict to Backend]
```

E. PROMPT ENGINEERING & PEDAGOGICAL LEVELING
================================================================================
1. Philosophy:
The AI Module does not rely on open-ended "chat" prompts. Prompts are treated
as strict functional specifications. The prompt builder (`prompts.py`) enforces
pedagogical structure while Gemini's native schema injection enforces data structure.

2. Level-Specific Pedagogical Guidelines:
The module alters the educational tone and depth according to `difficulty_level`:

- Beginner Level:
  "Focus on simple definitions, intuitive analogies, and basic foundational
   examples suitable for a novice learner."
  * Example prompt snippet:
    Target Difficulty Level: Beginner
    Pedagogical Guidelines: Focus on simple definitions, intuitive analogies...

- Intermediate Level:
  "Focus on precise technical terminology, underlying mechanisms and architecture,
   and practical real-world usage examples."
  * Eliminates basic analogies and introduces structural mechanics.

- Advanced Level:
  "Focus on deep system internals, subtle edge cases, architectural and design
   trade-offs, and performance optimization."
  * Pushes the student into concurrency, memory layouts, time-complexity bounds,
    and distributed failure modes.

3. Structural Instructions Inside the Prompt:
Every prompt deterministically contains:
- Detailed Explanation: Comprehensive topic explanation tailored to the tier.
- Revision Notes: Between 3 and 5 concise summary bullet points.
- Practice Quiz: Exactly 12 distinct, topic-relevant multiple-choice questions.
  * Each question must provide exactly four distinct options.
  * Each question must designate one correct answer that identically matches
    one of the four options.

4. Determinism:
Tested in `test_prompts.py`: Given the same inputs, `build_prompt` produces
identical string output byte-for-byte (`test_deterministic_output`).

F. GEMINI API INTEGRATION & STRUCTURED OUTPUT MECHANICS
================================================================================
1. Initialization & Key Retrieval:
`GeminiService` reads the API key from:
a) The explicit constructor parameter `api_key`, or
b) `os.environ.get("GEMINI_API_KEY")`.
If neither is present, it immediately halts with:
`ValueError: GEMINI_API_KEY environment variable is not set...`

2. Selected Model:
The service defaults to `DEFAULT_GEMINI_MODEL = "gemini-3.5-flash-lite"`.
- Rationale: During our architectural audit, legacy models (`gemini-2.5-flash`)
  returned 404s for newer projects, and larger models (`gemini-3.8-flash`)
  occasionally experienced 503 high-demand capacity spikes. `gemini-3.5-flash-lite`
  proved fast, reliable, and fully compliant with Pydantic JSON schemas.
- Caller Override: The model can be dynamically overridden by setting the
  `GEMINI_MODEL` environment variable (e.g., `gemini-3.8-flash`).

3. Structured Output Injection:
Instead of asking Gemini to "please format as JSON" in the prompt text, the
module uses Gemini's native structured outputs engine:
```python
config = types.GenerateContentConfig(
    response_mime_type="application/json",
    response_schema=LearningModule,
    temperature=0.3,
)
```
This forces Gemini's decoder to constrain token generation to valid JSON tokens
matching the OpenAPI representation of `LearningModule`.

4. The OpenAPI 3.0 Compatibility Solution (`_strip_additional_properties`):
In Pydantic v2, setting `extra="forbid"` generates a JSON schema containing
`"additionalProperties": false`. However, Google Gen AI's backend schema
validator currently rejects the `additional_properties` key with:
`400 INVALID_ARGUMENT: Unknown name "additional_properties"`.

To solve this without sacrificing strict validation:
We attached `json_schema_extra=_strip_additional_properties` to `ConfigDict`.
This function removes `"additionalProperties"` from the exported OpenAPI schema
sent over the wire to Google, while Pydantic still strictly forbids extra fields
locally when validating the response in Python.

5. Secret Sanitization:
When an error occurs (such as an invalid API key, network timeout, or 503 rate limit),
raw exception strings often contain the caller's private API key in the URL or
header dump.
In `gemini_service.py`:
```python
clean_msg = str(api_err).replace(self._api_key, "[REDACTED]")
raise RuntimeError(f"Gemini API request failed: {clean_msg}") from None
```
This guarantees that API keys never leak into backend server logs, stack traces,
or student-facing HTTP error responses.

G. DATA SCHEMAS & STRICT CONTRACT ENFORCEMENT
================================================================================
The data models in `ai_module/schemas.py` enforce strict integrity rules.

1. `QuizQuestion` Schema:
- `question` (`str`): Validated to be non-empty and non-whitespace.
- `options` (`list[str]`):
  * Field validator enforces `len(options) == 4`.
  * Enforces that every option is a non-empty string.
  * Enforces uniqueness: `len(set(options)) == 4` (no duplicate choices).
- `correct_answer` (`str`):
  * Model validator enforces `correct_answer in options`.
- `extra="forbid"`: Disallows hallucinated extra fields.

2. `LearningModule` Schema:
- `topic` (`str`): Validated non-empty string.
- `difficulty_level` (`Literal["Beginner", "Intermediate", "Advanced"]`):
  Restricted to exactly these three case-sensitive values.
- `explanation` (`str`): Validated non-empty string.
- `notes` (`list[str]`):
  * Field validator enforces `3 <= len(notes) <= 5`.
  * Every note bullet must be a non-empty string.
- `quiz` (`list[QuizQuestion]`):
  * Field validator enforces `len(quiz) == 12`.
  * Exactly 12 questions are required. 11 or 13 questions immediately raise
    a `ValidationError`.

3. Prompting vs. Validation Enforcement (Crucial Distinction):
- Requested via Prompt: Topic depth, tone, pedagogical clarity, question relevance.
- Enforced via Code/Pydantic: Exactly 12 questions, exactly 4 choices per question,
  all choices distinct, correct answer present in choices, between 3 and 5 notes,
  valid difficulty literals, and zero unauthorized extra fields.

4. Illustrative Example Output Structure:
```json
{
  "topic": "Python Memory Management",
  "difficulty_level": "Beginner",
  "explanation": "Python manages memory automatically using a private heap, reference counting, and a cyclic garbage collector...",
  "notes": [
    "Variables are references pointing to memory blocks, not the data itself.",
    "Reference counting deletes objects immediately when count drops to zero.",
    "A cyclic garbage collector resolves circular reference chains."
  ],
  "quiz": [
    {
      "question": "What is Python's primary mechanism for tracking object lifecycles?",
      "options": [
        "Reference counting",
        "Manual malloc/free",
        "Mark and sweep only",
        "Linear scan allocator"
      ],
      "correct_answer": "Reference counting"
    }
    // ... exactly 11 additional valid QuizQuestion objects
  ]
}
```

H. DIFFICULTY ADAPTATION LOGIC & BOUNDARY BEHAVIOR
================================================================================
The adaptive engine is implemented in `ai_module/difficulty.py` in the function:
`calculate_next_level(current_level: str, score_percentage: Union[int, float]) -> str`

1. The Mathematical Adaptation Rules:
- Rule 1 (Promotion):
  $\text{Score} \ge 80.0\% \implies$ Advance difficulty level by +1 tier.
  (Beginner $\rightarrow$ Intermediate, Intermediate $\rightarrow$ Advanced).
- Rule 2 (Demotion):
  $\text{Score} < 50.0\% \implies$ Decrease difficulty level by -1 tier.
  (Advanced $\rightarrow$ Intermediate, Intermediate $\rightarrow$ Beginner).
- Rule 3 (Maintenance):
  $50.0\% \le \text{Score} < 80.0\% \implies$ Maintain the current difficulty level.
  (Student demonstrated adequate comprehension but has not mastered the material).

2. Boundary Clamping:
- Floor constraint: A `Beginner` scoring $< 50\%$ cannot go lower than `Beginner`.
- Ceiling constraint: An `Advanced` student scoring $\ge 80\%$ cannot go higher
  than `Advanced`.

3. Comprehensive Boundary Transition Matrix:
Starting Level | Quiz Score (%) | Next Level    | Transition Outcome
-------------- | -------------- | ------------- | ------------------
Beginner       | 0.0%           | Beginner      | Clamped at floor
Beginner       | 39.99%         | Beginner      | Clamped at floor
Beginner       | 49.99%         | Beginner      | Clamped at floor
Beginner       | 50.0%          | Beginner      | Maintained (lower boundary)
Beginner       | 79.99%         | Beginner      | Maintained (upper boundary)
Beginner       | 80.0%          | Intermediate  | Promoted (lower boundary)
Beginner       | 100.0%         | Intermediate  | Promoted
Intermediate   | 0.0%           | Beginner      | Demoted
Intermediate   | 49.99%         | Beginner      | Demoted (upper boundary of demote)
Intermediate   | 50.0%          | Intermediate  | Maintained (lower boundary)
Intermediate   | 79.99%         | Intermediate  | Maintained (upper boundary)
Intermediate   | 80.0%          | Advanced      | Promoted (lower boundary)
Intermediate   | 100.0%         | Advanced      | Promoted
Advanced       | 0.0%           | Intermediate  | Demoted
Advanced       | 49.99%         | Intermediate  | Demoted (upper boundary of demote)
Advanced       | 50.0%          | Advanced      | Maintained (lower boundary)
Advanced       | 79.99%         | Advanced      | Maintained (upper boundary)
Advanced       | 80.0%          | Advanced      | Clamped at ceiling
Advanced       | 100.0%         | Advanced      | Clamped at ceiling

4. Input Validation & Security:
- Rejects non-numeric types (e.g., `calculate_next_level("Beginner", "80")` or `None`).
- Rejects Python booleans (`True`/`False` are subclasses of `int` in Python, so
  an explicit `isinstance(score, bool)` guard protects against this).
- Rejects `math.isnan(score)` and `math.isinf(score)`.
- Rejects out-of-bounds scores ($< 0.0$ or $> 100.0$).
- Rejects unapproved or incorrectly cased levels (e.g., `"beginner"` or `"Expert"`).

5. Rule-Based vs. Machine Learning Distinction:
Varun should emphasize this during presentations:
This is a deterministic, rule-based pedagogical policy (expert system logic),
NOT a trained machine learning model. It does not use weights, gradient descent,
or speculative heuristics. It provides predictable, transparent, and auditable
educational progression.

J. STEP-BY-STEP EXAMPLE EXECUTION TRACE
================================================================================
To explain how data travels through the system during a live demo or presentation:

1. Student Request:
A student requests a lesson on "Binary Search Trees" at the "Beginner" level.

2. Invocation:
The backend calls:
```python
module_data = generate_adaptive_content(
    topic="Binary Search Trees",
    difficulty="Beginner"
)
```

3. Internal Lifecycle:
- `adaptive_tutor.py` validates `"Binary Search Trees"` (non-empty string) and
  `"Beginner"` (valid literal).
- `GeminiService` reads `$env:GEMINI_API_KEY` and initializes `genai.Client`.
- `prompts.build_prompt` injects Beginner guidelines: "Focus on simple definitions,
  intuitive analogies, and basic foundational examples..."
- Gemini generates structured JSON matching the `LearningModule` schema.
- Pydantic validates the response: exactly 12 questions with 4 distinct options each.
- Returned as a Python dictionary.

4. Student Takes the Quiz:
- The frontend renders the 12 questions.
- The student answers 11 questions correctly and misses 1.

5. Adaptation Calculation:
- Backend evaluates: $\text{score} = (11 / 12) \times 100 = 91.67\%$.
- Backend calls:
```python
next_level = calculate_next_level(current_level="Beginner", score_percentage=91.67)
```
- Since $91.67\% \ge 80.0\%$, `calculate_next_level` returns `"Intermediate"`.
- The student is congratulated and their next lesson is automatically upgraded!

K. SECURITY, KEY MANAGEMENT, AND OPERATIONAL LIMITATIONS
================================================================================
1. Credential Security:
- Zero Hardcoded Keys: The codebase contains zero API keys. Grep audit confirmed
  no secrets exist in source code or git history.
- Git Exclusion: The root `.gitignore` explicitly ignores `.env`, `*.env`,
  `.venv/`, and `__pycache__/`.
- Runtime Redaction: Any exception message that could contain the API key is
  programmatically cleansed with `.replace(self._api_key, "[REDACTED]")`.

2. Operational Limitations & Edge Cases:
- Network Requirement: Live content generation requires active internet connectivity
  to communicate with Google's API servers.
- Model Availability & Latency: While `gemini-3.5-flash-lite` typically responds
  in 1.5 to 3.5 seconds, public network traffic or Google API demand spikes can
  cause latency or transient 503 errors. The backend should implement retry logic.
- Hallucination Mitigation: While LLMs can hallucinate factual nuances, our system
  mitigates this via:
  * Strict low temperature (`temperature=0.3`).
  * Explicit pedagogical guidelines.

3. Five Likely Faculty Questions & Accurate Defense Answers
--------------------------------------------------------------------------------
Q1: "Why did you use rule-based logic for difficulty adaptation instead of training
     a Machine Learning model or asking Gemini to decide?"
Answer:
"That was a deliberate architectural decision. Using an LLM or an unconstrained ML
model to adjust difficulty introduces non-determinism, latency, and potential bias.
A student who scores 85% must be guaranteed a promotion according to clear pedagogical
rules. Rule-based logic is instant (0ms latency), 100% predictable, auditable, and
free of token costs, while Gemini is reserved for what it does best: rich pedagogical
content generation."

Q2: "How do you guarantee that Gemini will always return exactly 12 questions and
     not hallucinate 10 or 15?"
Answer:
"We enforce this at two layers. First, at the API level, we provide the Pydantic
`LearningModule` schema to Gemini's `response_schema` configuration parameter,
which constrains the model's token output to our schema. Second, at the Python level,
our Pydantic schema contains a `@field_validator('quiz')` that explicitly checks
`len(quiz) == 12`. If the output deviates in any way, a `ValidationError` is raised
immediately and handled before reaching the user."

Q3: "What model are you using, and what happens if Google's API goes down or rate limits you?"
Answer:
"We configured `gemini-3.5-flash-lite` as our default model because of its fast
response times and high availability, while allowing overrides via the `GEMINI_MODEL`
environment variable. If Google's API encounters rate limits or service disruptions,
our `GeminiService` intercepts the `APIError`, redacts the secret API key so it is
never leaked in logs, and raises a sanitized `RuntimeError`. The backend then catches
this and returns an HTTP 503 Service Unavailable with a user-friendly retry message."

Q4: "Why did you create a custom `_strip_additional_properties` function in schemas.py?"
Answer:
"In Pydantic v2, specifying `extra='forbid'` generates `"additionalProperties": false`
in the OpenAPI schema. However, Google Gen AI's backend schema parser currently rejects
the `additional_properties` key with a 400 Invalid Argument error. To resolve this
without sacrificing security, our custom schema hook strips `additionalProperties`
from the schema payload sent to Google, while Pydantic still enforces strict
`extra='forbid'` locally in Python when parsing the returned JSON."

Q5: "How does your module ensure that the correct answer is actually one of the choices?"
Answer:
"We use Pydantic's `@model_validator(mode='after')` inside the `QuizQuestion` model.
After the question and choices are loaded, the validator executes:
`if self.correct_answer not in self.options: raise ValueError(...)`.
Additionally, we enforce that `len(set(self.options)) == 4`, ensuring all four
options are distinct. This completely eliminates questions with duplicate or
missing answers."
